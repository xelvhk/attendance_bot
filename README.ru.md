# attendance_bot

Telegram-бот для учёта рабочего времени, расчёта баланса и экспорта истории посещаемости в CSV. Данные хранятся в SQLite и разделяются по Telegram-чатам, поэтому один экземпляр бота может работать в личных чатах и настроенных группах.

Язык: [English](README.md) | **Русский**

![Стартовый экран](docs/screenshots/start.svg)

## Возможности

- Отметки прихода и ухода, больничного, отпуска, отгула и сокращённого дня.
- Статистика за неделю и месяц, баланс времени и полная история.
- Экспорт данных в CSV из интерфейса бота.
- Индивидуальный UTC-сдвиг пользователя через `/tz`.
- Раздельные данные и администраторы для каждого группового чата.
- Включение и администрирование групп командами `/setup_chat`, `/add_admin`, `/remove_admin` и `/disable_chat`.
- Хранение данных в SQLite и работа через long polling без публичного HTTP-эндпоинта.

## Быстрый старт

```bash
git clone https://github.com/xelvhk/attendance_bot.git
cd attendance_bot
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python main.py
```

Перед запуском настройте `.env`:

```env
BOT_TOKEN=your_telegram_bot_token
ADMIN_IDS=123456789,987654321
DB_PATH=attendance.db
```

- `BOT_TOKEN` обязателен.
- `ADMIN_IDS` — необязательный список ID глобальных администраторов через запятую.
- `DB_PATH` по умолчанию равен `attendance.db`.

## Настройка группы

Добавьте бота в группу и выполните `/setup_chat` от имени администратора Telegram-группы. До завершения настройки команды учёта в этой группе отключены.

Основные команды:

- Учёт: `/in`, `/out`, `/mk`, `/uvc`, `/uvs 6`, `/short_day 7`, `/vacation`, `/personal_day`.
- Статистика: `/week`, `/month`, `/balance`, `/all_stats`, `/manual 2024-12-31 09:00:00-18:00:00`.
- Администрирование: `/chat_info`, `/chat_admins`, `/add_admin`, `/remove_admin`, `/disable_chat`.

## Деплой на Amvera

Файл [`amvera.yml`](amvera.yml) запускает `main.py` и подключает постоянное хранилище в `/data`.

1. Добавьте `BOT_TOKEN` как защищённую переменную окружения.
2. При необходимости добавьте `ADMIN_IDS`.
3. Установите `DB_PATH=/data/attendance.db`, чтобы база сохранялась между деплоями.
4. Выполните деплой и убедитесь, что в логах есть `Starting bot` без ошибки конфигурации.

Бот использует Telegram long polling. `containerPort` — параметр платформы, а не публичный эндпоинт бота.

## Архитектура

- `main.py` — запуск приложения, регистрация команд и polling.
- `handlers/` — пользовательские, административные и fallback-обработчики Telegram.
- `services/` — учёт, статистика, часовые пояса, управление чатами и доступ к SQLite.
- `config_data/` — загрузка конфигурации из окружения.
- `keyboards/` и `lexicon/` — русскоязычные элементы интерфейса и сообщения.
- `tests/` — модульные и граничные тесты сервисов.
